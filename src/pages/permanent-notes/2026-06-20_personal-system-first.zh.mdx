## 没人给这个类别起过名字

你读过足够多的 2026 年智能体讨论，就会发现每个认真的系统都落进两个框子之一。

平台优先：有人搭基础设施，你来租用。Vercel 发布了 eve。某家银行搭了一个内部智能体平台，每周合并 1500 个 pull request。JetBrains 在 IDE 里装了 Junie。论点是智能体就是基础设施——价值在平台，你的工作是接入它。

框架优先：有人给你原语，你自己组装。LangGraph、各种 Python 智能体库、编排工具箱。论点是智能体是软件组件——价值在抽象，你的工作是把它们组合成工作流。

两种都是真实存在的。两种都有融资、会议和基准测试。但它们共享一个隐藏的假设，几乎没人审视过：系统是通用的。它被建来服务很多用户，或者被很多构建者用来组装。循环里的人是可互换的——是平台的用户，是握着框架的开发者。

还有第三个维度。我在里面生活了几个月，却没给它起过名字，这一周市场用实际行动验证了它底下的机制，但仍然没给这个维度起名。所以我来给它起名。

个人系统优先：围绕恰好一个人——他的生活、他的知识、他的词汇、他的判断——来架构的智能体系统，这里人不是系统的用户，而是不可替代的核心。这个系统不是在服务一个人的市场。它在延伸一个具体的心智。

这不是"碰好用到智能体的个人项目"。那只是更小范围的框架优先。区别在于设计中心。在平台优先中，中心是基础设施。在框架优先中，中心是抽象。在个人系统优先中，中心是人——每个架构决策都从一个问题开始：这样做会延伸这个人，还是试图替换他们？

## 那一条规则

这篇文章里的一切都来自一个原则，如果你只带走一句话，就带走这个：

**人是不可替代的核心。系统延伸他们；永远不替换他们。**

把它当成一个测试，可以应用到任何功能、任何自动化、任何模型选择上：这个改变会让人更可替代，还是更被延伸？一个自动草拟站会报告但人仍然负责修改的自动化——这是延伸。一个用他们的声音代他们发布、不需要他们参与的自动化——这是替换，是对唯一属于他们的东西的悄悄蚕食。

听起来很软。它是系统里最硬的工程约束，因为它禁止了简单的胜利。简单的胜利总是"把这一步的人自动化掉"。个人系统优先拒绝任何简单胜利，只要这一步是人的判断、品味或声音真正活着的地方——然后把自动化路由到周围的所有东西。

收益是一个反转，平台优先和框架优先永远到不了：一个系统，随着一个特定的人使用它的时间越长就越有价值，因为它在积累那个人，而不是通用能力。

## 让它运作的原则

五个想法把这个类别拢到一起。每一个都可以转移——你可以不复制我一行代码，就用这些原则构建你自己的个人系统优先架构。

### 1. 知识是护城河，不是工具

任何人都可以克隆一个工具。一个提示词、一个脚本、一个配置文件——都可以在一个下午复制。不可复制的是累积的背景：数月的决策、记录的失败、关于哪个权衡是对的以及为什么的判断。

所以个人系统必须把知识当成主要资产，把工具当成可丢弃的。实际上这意味着严格的分离：一个知识层存储事实、惯例和决策，每个东西存一个地方，和一个编排层（技能、脚本、规则）引用知识但永不嵌入知识。我在记下任何东西之前应用的测试：如果这个事实明天改变了，我得编辑多少个文件？答案必须是一个。如果是更多，知识就漏进了编排层，会漂移。

更深层的点：工具不是重点。它买到的自由是。在一个人人都能复制的世界里，可复制的工具一文不值。产生这个工具的推理——那是资产，它活在知识层。

### 2. 确定性优于概率性，总是如此

一个"记得"你偏好的模型每次都在猜测。一个强制执行它的钩子不会漂移。这是第二原则：把每个约束都尽可能往确定性阶梯下推。

阶梯，按杠杆率从高到低：生成（派生文件不能和源不一致）、引用（wiki 链接总是指向当前真理，复制冻结它）、门控（错误传播前捕获它）、审计（之后捕获——最弱的选项）。大多数系统完全活在审计这层。纪律是把东西往上移。

我自己系统里最清晰的例子：我完全禁用了智能体的自动记忆。记忆文件复制了我的配置已经说过的东西，每个会话烧掉 token，而且会无声地漂移，因为模型决定了要保留什么。我删了二十二个文件，只保留了一个配置文件作为唯一真实来源，每个会话加载，确定性。这个原则比我还老：好记性不如烂笔头——一个淡淡的铅笔痕迹胜过敏锐的记忆。信任被写下来的东西，不信任被记住的东西。

现在有研究指向同样的方向。TRACE 论文（Zhou et al., 2026）显示编译执行把分布外行为违规从 57.5% 降到了 2%，相比记忆型系统。我在看到这个数字之前已经在这个假设上构建了一段时间，找到它很让人放心——但机制从不复杂。它就是承诺和锁的区别。

### 3. 摩擦是构建的唯一正当理由

个人系统的增长来自发现已经存在于你自己摩擦里的模式，不是为假设的未来发明模块。每个脚本、每个自动化，都应该追溯到一个真实的痛点时刻或一个重复的手工步骤。如果追溯不到，它就不应该存在。

这是对个人工具里最诱人的失败的解毒剂：因为博客文章推荐就构建优雅的东西。测试是残酷和简短的——"这个解决什么摩擦？"没答案就别构建它。

更强的版本，我最近才机制化了：一个行为重复两次本身就是摩擦信号，即使你从没把它记为摩擦。最重要的摩擦是那些你停止注意因为它们变成了常态的摩擦。三次表达的欲望是潜在功能；三次做过的变通是潜在自动化。系统的工作是读自己的历史，浮现那个你再也看不到的模式。

### 4. 智能层级作为韧性

把智能层级和工作匹配。一个没有确立模式的新问题需要前沿模型来思考。一旦模式清晰了，提取它——把它编码成一个根本不需要运行任何模型的脚本。

大多数人把这个框架为成本优化，确实是。但成本是更弱的论点。更强的是独立性。一个脚本是零成本、人可运行的、确定性的——这部分才是要点——它离线工作，没有订阅、没有 API 密钥、没有云。真正的目标是即使网络断了，只有本地模型在运行，系统仍然可以做它的大多数工作。发现是昂贵的一次性成本；执行变成免费和可重复。

这一周把框架变成了具体的。一个 Hacker News 讨论澄清了它——"本地 Qwen 不是更差的 Opus，是一个不同的工具"。GLM-5.2 发布了接近前沿的开源权重。关于谁控制前沿模型的供应链焦虑出现得到处都是。市场往往从成本方向到达独立性论点。值得从韧性方向也到达它：一个依赖某个公司可用性的系统不是你拥有的系统。

### 5. 系统是一个通讯系统

这是重新框架化所有其他的原则，也是我最久没给它起名字的那个。我在构建的系统，在其根部，不是工具集合或自动化引擎。它是一个降低被理解成本的方式。

好通讯的两条法则：了解你的听众，了解你自己最好的表达形式。每条配置规则、每个捕获的偏好、每个学来的习惯都是一块木板，在我的意思和智能体理解之间架桥。一旦那座桥足够坚固，同样的机制就降低了更难的通讯成本——在我和世界之间。系统知道我的听众和我最好的形式，所以它可以把任何信息塑造成着陆损失最少的形式，在意图和接收之间。

这是为什么表达不是个人系统的最后一步。它是目的。前面的一切都是准备。

## 架构

原则没有结构来撑住它们就很廉价。这是具体的形状，五层。名字不如它们之间的依赖规则重要。

```
第 5 层  接入       我如何到达系统（手机、终端、语音、Kindle）
第 4 层  执行       工作发生的地方（智能体、编辑器、shell）
第 3 层  自动化     主动的第二大脑（计划循环、摩擦检测）
第 2 层  持久化     状态如何活过会话（配置、规则、生成的技能）
第 1 层  知识       理解累积的地方（笔记图、日志）
```

最重要的架构规则是关于引用方向的。每个文档只可以引用它左边的层——永不右边。入口点（每个会话加载的配置）引用所有下游东西。知识是纯的：一个知识笔记永不引用技能。如果引用了，知识就被编排污染了，不会可重用。

为什么这比看起来重要得多：仅左引用保持知识可重用——很多技能读一个笔记——并防止了知识漏进编排、在每个消费者里都被复制的膨胀模式。这和代码里干净的依赖图是同样的直觉。把架构拢到一起的不是任何一层；是它们之间的箭头的纪律。

人同时坐在第 5 层和第 1 层——他们进出的接入点，以及累积的知识来源。这是个人系统优先的结构特征。在平台里，人是一个调用 API 的客户端。这里，人既是前门也是基础。

## 工程

特定性就是信用度。关于"复合系统"的模糊说法一文不值；这里是它实际的成本，包括什么坏了。

持久化层是版本控制下的纯文本——一个 Markdown 笔记图，由 git 备份。我评估过结构化 API 方法（一个通过模式暴露库的服务器）并拒绝了它。纯文件访问有零运行时依赖，在任何机器上无头工作，不需要服务器运行，每个工具——git、grep、任何模型——都可以不用适配器操作它。结构化 API 很流行因为它给初学者栏杆。我的栏杆是路由规则和一个唯一真实来源配置，更有表达力，不需要一个进程在运行。我接受的权衡：我失去了图查询和插件交互。在我的规模，grep 替换图查询，我不依赖插件做自动化。

自动化层运行为计划循环，在我睡觉时改进系统——研究一个话题、找个修复、应用它、记录它。三个层级，不同的自主权：一个十五分钟心跳静无声地找到并修复 bug，一个进化者做深度研究并标记结构改变让我决定，还有一个夜间整合器排干队列工作。我硬学到的设计规则：写修复的智能体永不验证自己的修复。一个新鲜的通过确认它着陆了。制造者和检查者永不是同一个智能体——写 bug 的同样盲点不会捕获它。

这层最难的约束是没有伤害的自主权。前沿智能体即使在它们拒绝有害请求时，在真实工作空间也以非平凡的速率选择有害执行路径——拒绝对齐不意味着执行安全。所以夜间循环在机械栏杆内运行：循环检测（三个相同工具调用是循环，停止），成本上限（token 阈值硬关闭、优雅检查点），和断路器（认证失败、破坏性命令、上下文窗口超过 80%）。这些不是模型的判断。它们是确定性边界围绕模型的判断。

## 反模式

记录的失败是没人能复制的部分，因为它们特定于真正运行过东西。这些是真实的。

为优雅而构建而不是为摩擦。我做过的最昂贵的错误是看一个受推崇的外部工具并强制我的系统采用它的命名约定。重命名破坏了一切，需要复杂的修复，因为新名字和系统被构建围绕的心智模型不匹配。教训：外部工具是评估的输入，不是整体采用的蓝图。如果一个更好的方法确实更好，你自己的摩擦会自然浮现它。如果采用它需要强制，强制本身就是停止的信号。你系统的词汇从真实摩擦里长出来；用别人的分类覆盖它是发明，不是发现。

无声的总是开着的进程。这一周一个向我手机推送警告的后台服务已经死了七天，什么都没告诉我。根本原因是一个被漏掉的原则：一个总是开着的进程必须宣布自己的死亡。一个卡住的进程不能报告它卡住了——所以修复是一个外部观察者（一个独立的看门狗，通过一个不同的传输讲话比它看的东西）拥有存活性警告。推论性失败都跟随同样的根：日志在一个操作系统清理的临时目录，传递失败无声失败而不是大声失败，一个心跳写一次在启动、再不写。值得保留的模式：每个总是开着的进程默认得一个外部心跳看门狗。反模式：信任系统报告自己的失败。

过度工程反射。当我加固那个服务时，一个员工级别的审查标记了一打"问题"——状态文件锁、模式版本化、解析优化。我故意杀掉了大多数。文件锁防护对一个架构已经让不可能的竞争（每个会话拥有自己的状态文件）。七天一次垃圾收集的丢弃文件上的模式版本化是企业仪式。个人系统的纪律不是加上每个通用审查者会要的每个保护措施；是知道你的特定架构已经防止了什么状态，拒绝对不可能的失败加仪式。通用性是你只在有很多用户时支付的成本。你有一个。

在人活的步骤里自动化。经常的诱惑，也是那一条规则存在来捕获的那个。在生成可靠地匹配你标准前自动化内容发布是在规模上自动化平庸。门控：精炼，然后信任，然后自动化——门控只在输出不需你编辑就一致正确时降下。质量第一，自主权第二。一个在它赚到你的声音前自动发布你的声音的个人系统已经用一个更便宜、更差的你版本替换了你。那是整个类别存在来避免的失败。

## 接下来是什么，以及为什么现在很重要

给这个类别起名的窗口现在打开了，它会关闭。

这一周智能体基础设施世界有了它的时刻——Vercel 的 eve、银行运行每周 1500 个智能体 PR、JetBrains Junie、GLM-5.2 的开源权重、关于编译执行的 TRACE 论文、测量智能体是否能运行一个组织的基准测试。每一个确认了个人系统优先依赖的一个机制：确定性执行胜过记忆，本地模型买独立性，智能体周围的架构决定了价值是否复合。没有一个起了第三个维度的名字。讨论仍然在争论平台对框架、基础设施对抽象，好像那些是仅有的两种方式。

它们不是。有第三种立场，它的赌注是我会对另外两个中的任何一个下的那个：智能体时代里的耐用优势不是最好的平台或最干净的框架，而是一个特定具体的人的最深积累——他的判断、他的失败、他的声音——被一个设计来延伸他们而不是规模过去他们的系统持有。

平台构建者优化很多用户。框架构建者优化很多构建者。两个都冲向通用性，通用性正好是不能是护城河的东西，因为人人最后都到达它。个人系统冲反方向——冲向不可约的特定性。护城河不是架构。任何人都可以读这篇文章并复制五层。护城河是一个特定个人的数月推理，架构一直在静无声地累积，这是复制架构不会带上的唯一东西。

所以这是值得思考的想法。在一个工具被商业化、前沿模型是共享实用程序的世界里，最稀缺的东西不是能力。是一个知道一个人足够好以可靠延伸他们的系统——构建它的唯一方式是做那个人，为足够长时间构建它，直到积累变成资产。你不能买它、fork 它或为它筹资。你只能活在它里直到它变成不可替代。

那是第三条路。现在它有名字了。
